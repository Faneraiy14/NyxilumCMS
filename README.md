# Nyxilum CMS

Власний загальний CMS-продукт на чистому PHP + MySQL, без фреймворку.
Почався як експеримент ("спочатку як експеримент, викладемо, якщо
вийде щось годне"), назва — на честь екосистеми Nyxilum
(NyxilumLang/Db/Mcp/Node).

Ключова відмінність від типової саморобної CMS: один гнучкий стіл
`content` із довільним текстовим `type` (page/post/будь-що своє) замість
окремої таблиці на кожен вид контенту — новий тип означає новий шаблон
у `templates/`, не нову міграцію.

## Можливості

- Гнучкий контент довільних типів (`type-{type}.php` шаблон автоматично
  підхоплюється, якщо існує — інакше рендериться `page.php`)
- Категорії — одна гнучка many-to-many таксономія (замість окремих
  систем "категорій" і "тегів")
- Відкладена публікація (`publish_at`) — запис стає видимим лише після
  настання вказаного часу, попри статус "Опубліковано"
- Ролі admin/editor із реальним розмежуванням доступу (не лише сховані
  посилання в навігації — перевірено напряму по URL)
- 2FA (TOTP, RFC 6238) — власна реалізація, без composer-залежностей
- Журнал дій адмінів + дашборд зі швидкими діями й стрічкою останніх дій
- SEO: власні meta_title/meta_description на запис, Open Graph і
  Twitter Card теги, sitemap.xml, RSS-стрічка (`/feed.xml`)
- Пошук по сайту, попередній перегляд чернеток (`/preview/{slug}`)
- Медіа-бібліотека з реальною перевіркою MIME-типу файлу (не довіряє
  клієнтському Content-Type)
- Export/import повного стану сайту (`.tar`, вбудований `PharData`,
  без залежності від розширення `zip`)

## Технології

- PHP 8.1+ (розроблено й перевірено на 8.5), MySQL/MariaDB
- Без фреймворку, без Composer — прості `include`, router+array pattern
- Quill.js і qrcodejs підключаються з CDN (без build-кроку на фронтенді)

## Встановлення

1. Створи базу даних MySQL і користувача для неї.
2. Розгорни вміст `app/` на PHP-хостингу (чи локально через
   `php -S localhost:8097` з теки `app/`).
3. Відкрий сайт у браузері — за відсутності `app/config.php` він сам
   перекине на `/install.php`. Заповни дані підключення до БД і
   першого адміна.
4. Встановлювач створює таблиці (`db/tables.sql`) і пише
   `app/config.php` (у git не потрапляє). Повторний запуск
   `/install.php` після цього навмисно заборонений (403) — видали
   `config.php` вручну, якщо справді потрібно перевстановити (сама
   база даних при цьому НЕ видаляється).

## Розробка

Без build-кроку — просто піднімай вбудований сервер PHP з теки `app/`:

```bash
cd app
php -S localhost:8097
```

`db/schema.sql` — документована версія схеми (з `CREATE DATABASE`),
`db/tables.sql` — та, яку реально виконує встановлювач. Тримати в
синхроні при кожній зміні схеми.

## Тести

PHPUnit-тести бʼють по РЕАЛЬНІЙ базі (не моки, не SQLite) — тому
`tests/bootstrap.php` жорстко відмовляється запускатись, якщо активна
база не містить `"test"` у назві (щоб випадковий запуск на реальному
сайті не видалив реальні дані). Локально найпростіше — одноразовий
Docker-контейнер:

```bash
docker run --rm -d --name nyxilum_cms_test_db \
  -e MYSQL_ROOT_PASSWORD=root -e MYSQL_DATABASE=nyxilum_cms_test \
  -p 13309:3306 mysql:8.0

mysql -h127.0.0.1 -P13309 -uroot -proot nyxilum_cms_test < app/db/tables.sql

composer install
DB_HOST=127.0.0.1 DB_PORT=13309 DB_NAME=nyxilum_cms_test DB_USER=root DB_PASS=root composer test
```

Кожен тест сам прибирає за собою в `tearDown()` (тестові рядки мають
префікс `__phpunit_test_`).
